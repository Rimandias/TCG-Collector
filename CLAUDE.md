# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PokéTracker (package name "TCG-Collector") — a Pokémon TCG collection/trading tracker, PT-BR UI, mobile-first React SPA. Two independent processes: **frontend** (repo root, React 19 + Vite) and **backend** (`server/`, Express). The frontend never talks to the Pokémon TCG API directly — it always goes through the Express backend, which holds the API key and proxies/caches catalog data. Auth, user data, friends, and trades live in Supabase (Postgres + Auth); the Express backend is the only thing with the Supabase **service role** key.

Deploy targets: frontend on Vercel (custom domain `tcgcolecionador.com.br`), backend on Render (`api.tcgcolecionador.com.br`, behind Cloudflare). Both are configured to auto-deploy from `main` — the GitHub repo is public again (no longer needs the private-repo GitHub App re-auth workaround this note used to describe). That said, Render's auto-deploy was observed silently not firing on several consecutive pushes in one session (Vercel kept deploying fine the whole time) — if a push doesn't show up as a new deploy on Render's dashboard within a minute or two, don't assume it's in production; check `list_deploys`/the dashboard and trigger a manual deploy (`mcp__Render__trigger_deploy`) rather than assuming auto-deploy caught it. Root cause wasn't identified (webhook delivery, GitHub App permissions, and Render-side flakiness are all still on the table) — re-check github.com/settings/installations if it keeps happening.

## Commands

Frontend (repo root):
- `npm run dev` — Vite dev server on :3000, proxies `/api/*` to the backend (regex proxy in `vite.config.ts`, careful not to match the `api.ts` source file)
- `npm run build` — production build (also run before shipping to catch type/bundle issues)
- `npx tsc --noEmit` — typecheck

Backend (`server/`):
- `npm run dev` — `tsx watch src/index.ts` on :8787
- `npm run build` — `tsc -p tsconfig.json`
- `npm run codes:generate` / `codes:list` — manage premium access codes; the code-redemption gate itself is currently disabled (see `middleware/auth.ts` below), these scripts just manage the underlying data
- `npm run premium:set` — `scripts/revoke-premium.js`

No automated test suite exists (frontend or backend). Verification is: `tsc --noEmit` + `npm run build` on both sides, plus manual/Playwright E2E against a live Supabase project when UI behavior needs confirming (see Testing below).

## Environment

Frontend `.env.local`: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (safe to expose), optional `VITE_API_URL_PROXY_TARGET`.

Backend `server/.env`: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (secret — full DB access, bypasses RLS), `CLIENT_ORIGIN` (comma-separated list — needs both apex and `www` variants since Vercel redirects between them and CORS must match exactly), `PORT`. No API key needed for the catalog — see TCGdex note below.

Supabase project ref: `ihaogdkyrsfiywqiuogs`. Service-role keys are now the new `sb_secret_...` format (not a JWT) — `@supabase/supabase-js`'s `admin.auth.admin.createUser()` currently breaks on this format ("unrecognized JWT kid"); use a raw `fetch` to `/auth/v1/admin/users` instead when scripting user creation. Plain `.from(...)` queries and `listUsers()` are unaffected.

## Backend architecture (`server/src`)

- `index.ts` — helmet, CORS (multi-origin allow-list from `env.clientOrigins`), `express.json({ limit: '10mb' })` (collections with many cards + full variation/condition/language matrices get large — this was raised once already, be wary of shrinking it), a blanket rate limiter, then routers mounted at `/api/tcg`, `/api/tcg-jp`, `/api/users`, `/api/friends`, `/api/trades`, `/api/premium`, `/api/decks`. The catch-all error handler flattens every error to a generic 500 — when debugging a mystery 500, check server logs directly, the client response won't tell you anything.
- `middleware/auth.ts` — `requireAuth` validates the `Authorization: Bearer <supabase access token>` via `supabase.auth.getUser(token)`. `requirePremium` is currently a no-op (`next()`) — the access-code gate on trades/friend folders was intentionally removed for everyone, closed beta is over. The underlying `premiumStore.isPremiumUser` / code-redemption logic is still there and reversible, just not called from the route chain anymore.
- `userStore.ts` — `assembleFullUser` / `replaceUserData` assemble and persist the whole `FullUser` shape (profile, owned cards, friends, folders, wishlist) in one PUT. `replaceUserData` **upserts + diffs against what's already in the DB** (never blind delete-then-insert) for `user_cards`, `wishlist`, `trade_folders`, `trade_folder_cards` — this matters because two overlapping saves for the same user (e.g. the client's trade-folder auto-sync firing alongside another edit) used to hit `23505` duplicate-key errors under the old delete/insert pattern. Diffing against the DB (not a giant `NOT IN` filter) also matters because real collections run 700+ cards.
- `tradeStore.ts` / `routes/trades.ts` — trade state machine (see below).
- `routes/tcg.ts` — proxies/caches the western catalog (sets, cards, community price stats via `/card-stats/:cardId`) from **TCGdex** (`api.tcgdex.net`, `pt` locale) — this replaced pokemontcg.io intentionally, since TCGdex has Portuguese-language card data and needs no API key. `fallbackData.ts` is a small hardcoded catalog used if the upstream API is unreachable.
- `routes/tcgJp.ts` — same TCGdex source, different locale/series filter, for Japanese/Oriental collections. Kept as a separate router/cache from `tcg.ts` because the two catalogs serve different Home views, not because they're different upstream APIs.
- `routes/decks.ts` — CRUD for the Decks feature (`decks` + `deck_cards` tables, own router/rate-limiter, no `tradeStore.ts`-style state machine needed). Max 5 decks/user, max 60 cards/deck, both enforced here. `deck_cards.quantity` is what the *deck* needs, completely independent of `user_cards` — building a deck never reads from or writes to the user's collection. Cards replace via upsert+diff (`replaceDeckCards`, same reasoning as `syncKeyedTable` above, scoped down since a deck has one table not four). `routes/tcg.ts` additions that support this: `mapSet()` now also captures `code` (the short Limitless/PTCGO set code like "TEF") from TCGdex's `abbreviation.official` field (**not** `tcgOnline` — a wrong guess here that shipped once, caught only by live-testing the real TCGdex API since the sandbox couldn't reach it during dev); `extractVariantFlags()` now also returns `category` (Pokémon/Trainer/Energy — **localized**, TCGdex's `pt` locale returns `"Treinador"`/`"Energia"`, not the English names, so any category-matching code needs `decks.ts`'s `categorizeCard()` helper, never a raw string compare) and `legal: {standard, expanded}` per card. `POST /tcg/resolve-decklist` turns pasted-decklist lines (`"4 Beldum TEF 113"`) into card ids by matching `code` against a set then `number` within it — card numbers in the catalog are zero-padded (`"008"`), pasted lists usually aren't (`"8"`), so the match normalizes both sides (`normalizeCardNumber`) or nearly everything fails to resolve.

## Frontend architecture

- `App.tsx` — owns the authenticated `User`, active tab, and the **save pipeline**: every mutation goes through `handleUpdateUser`, which updates React state optimistically and debounces (500ms) a `PUT /api/users/me` via `persistUser`. `flushPendingSave` bypasses the debounce and is called before any point the user might navigate away (tab change, logout, `beforeunload`/`visibilitychange`) so a fast reload can't silently drop a save. A save still in flight blocks tab changes with a "Salvando..." overlay; F5/Ctrl+R while saving is intercepted to show a custom confirm dialog (the native `beforeunload` prompt's text can't be customized).
- `db.ts` — the card/variation data model helpers. Each owned card's `variations` is a sparse map that `getNormalizedVariations` expands to the full cross-product of `VARIATION_TYPES` (Standard/Foil/Reverse Foil/etc., see `types.ts`) × `CardCondition` (D/HP/MP/SP/NM) × optional per-language sub-entries (`ConditionDetails.languages`). **The aggregate `price`/`quantity` fields and the per-language ones are updated independently** (`setLanguagePrice` only touches the language entry) — code that reads price/quantity must check `languages` first or it'll silently miss data (this has caused real bugs: backfilled prices invisible in the UI, community stats excluding language-broken-down cards).
- `viewMode.ts` + `components/CardViewModeSelector.tsx` + `components/CardItem.tsx` — the shared list/grid-3/grid-6 view toggle (`CardViewMode`) used across Home, Collection, and every trade-folder view (own folders, wishlist, friend's folders). Grid-6 is desktop-only (`md:` breakpoint, 768px — the only responsive breakpoint convention in the app; most of the UI is otherwise mobile-only with no responsive variants, so don't assume a component adapts to desktop unless you check).
- `views/TradesView.tsx` + `components/FriendFolderBrowser.tsx` — trade folder browsing/management. `trade_folders.id` is a **global** primary key (not scoped per user), so folder ids are constructed as `` `${userId}-...` `` (see `defaultFolderId`) to avoid cross-account collisions — never go back to a bare literal id like `'default'`. Friend-folder card ordering always prioritizes wishlist > not-yet-owned > everything else (`getCardPriority`); preserve this when touching the render path.
- `components/TradeActionModal.tsx` + `trades.ts` — trade status state machine: `pending_response` → (`choose_payment` → `awaiting_payment_confirmation`, both sides `confirm`) or (`choose_offer` → `selecting_offer` → `awaiting_value_diff_confirmation`) → `completed`/`cancelled`. Choosing cash payment auto-confirms that side (no separate confirm click); only the card-for-card path has an explicit `submitTradeOffer` step.
- Styling: Tailwind is loaded via the **CDN script** in `index.html` (no build step, no `tailwind.config`) — this only works where the browser can reach `cdn.tailwindcss.com`; sandboxed/proxied environments need the requests routed through a local relay or Playwright route interception (see Testing).
- `views/DecksView.tsx` + `decks.ts` — deck builder, gated by nothing (no premium check, like trades). Deck-list screen shows up to `MAX_DECKS` (5) tiles, **horizontal/compact** (fixed `h-[72px]`, icon-left/text-right, 2/3-col grid) — a tall/vertical tile shipped once and was flagged as "muito ruim/muito grande", don't go back to that. Dashed `+`-with-label tile fills empty slots. Opening a deck reuses the app's normal `CardViewModeSelector`/`getCardGridClassName` (grid-3/grid-6/list) to render its cards — **not** `CardItem`, since that component's +/- edits `user.ownedCards` directly and decks need the opposite: the quantity stepper edits `deck_cards.quantity` (what the deck *needs*) and never touches the collection. Each `DeckCardTile` shows `owned/needed` (e.g. "2/4"), grayscales only when `owned === 0`, and shows a red "-N" badge when short — "owns some but not enough" stays in color, only true non-ownership is B&W. The deck tile grid and the in-deck legality tag (`Standard`/`Expanded`) both call the same `computeLegalTag()` (a deck is only "Standard" if *every* card is) so they can't drift. `parseDecklistText`/`formatDecklistText` (`decks.ts`) round-trip the Limitless/PTCGO-style pasted format (`"4 Beldum TEF 113"`); import resolution happens server-side (`/tcg/resolve-decklist`) and never guesses — unmatched lines are surfaced back to the user instead of silently dropped or mis-added. **Two separate label maps** for the 3 card categories: `DECK_CATEGORY_LABELS` (`decks.ts`) is the fixed English Pokémon/Trainer/Energy convention, used **only** for import/export text (must stay compatible with lists copied from outside the app); `UI_CATEGORY_LABELS` is the Portuguese Pokémon/Treinadores/Energias shown on-screen — don't merge these back into one, the export format isn't supposed to localize.
- Page header convention (title + subtitle), matched by `DecksView`'s list screen: `<h2 className="text-2xl text-slate-800">Title</h2>` + `<p className="text-slate-400 text-xs">Subtitle.</p>`, wrapped in `<div className="animate-in fade-in duration-500 px-6 pb-8 pt-4">` — see `TradesView.tsx`/`CollectionView.tsx` for the original. A view that doesn't follow this (e.g. used `p-4` + a small bold `<h2>`) reads as visually inconsistent with the rest of the app.

## Testing / running locally against real data

There's no seed/local DB — everything hits the real Supabase project.

**This machine (Windows, `Bash` tool = Git Bash) has direct outbound network access** — Supabase, `cdn.tailwindcss.com`, and TCGdex are all reachable straight from `curl`/the dev server, no relay needed. (An *earlier* session assumed a fully-isolated sandbox that couldn't complete TLS handshakes to external hosts and needed a `localhost:9999` HTTP→HTTPS relay + Playwright `context.route()` interception for CDNs — that pattern doesn't apply here; if a future session finds itself in that kind of sandbox instead, fall back to it.) `api.tcgdex.net` did 502 for a while during one session (real upstream issue, confirmed by retrying over tens of minutes) while `images`/other TCGdex hosts stayed up — if it happens again, don't assume it's a local network block, just retry later or fall back to `cards_cache`/`sets_cache`.

- `.env.local` (frontend) and `server/.env` (backend) exist locally already — created once by pulling the anon/publishable key via the `Supabase` MCP (`get_project_url`/`get_publishable_keys`, safe to expose) and asking the project owner to paste `SUPABASE_SERVICE_ROLE_KEY` into `server/.env` directly (never through chat if avoidable — it's secret, full DB access, bypasses RLS). Both files are gitignored; no need to recreate them each session.
- Playwright (`npx playwright install chromium`) works for browser-driven testing here — no `chromium-cli` installed, drive it with a small Node script (`import { chromium } from 'playwright'`) instead.
- Disposable test accounts only, pattern `sergioriman+e2<label><timestamp>@gmail.com`, created/deleted via the Supabase admin API, always cleaned up at the end of a test run.
- **Never touch these real accounts**: `sergioriman@gmail.com` (the project owner), `darkangelsergio@hotmail.com`, `samir.rimandias@gmail.com`.
- The trade-folder auto-sync (`TradesView.tsx`) only creates a friend's `trade_folders` row on the *client*, the first time that account visits the Trocas tab — a friend's folder won't be visible to test against until that account has logged in once and opened Trocas.
- Selectors when scripting Playwright against this app: the header search input and modal search inputs (e.g. `DecksView`'s card-search modal) share the substring "Buscar carta" in their placeholder — use the full placeholder text or scope to the modal container, a loose `input[placeholder*="Buscar carta"]` grabs the wrong one. Same idea for back buttons — the app header's back arrow and a view's own back button can share the exact same Tailwind classes.
